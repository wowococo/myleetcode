# 最长公共子串 —— 解题思路 + Go 实现

## 一、先搞清楚题目

**最长公共子串**（Longest Common Substring）和"最长公共子序列"是两码事，很多人会搞混，面试时一定要先澄清：

- **子串**：必须是**连续**的一段字符（比如 "abc" 是 "abcde" 的子串，但 "ace" 不是）
- **子序列**：可以**不连续**，只要保持相对顺序（"ace" 是 "abcde" 的子序列）

我们这里要找的是**连续**的最长公共部分。

## 二、暴力解法（先想最直观的，再优化）

**思路**：枚举字符串 A 的每个起点，再枚举字符串 B 的每个起点，从这两个起点开始逐字符比较，看能匹配多长。

- 时间复杂度：O(m × n × min(m,n))，因为每一对起点都要一直比较下去
- 这个方法能过，但不是最优解，面试官问"还能不能优化"时，就要往动态规划（DP）方向想

## 三、最优解思路：动态规划（DP）

### 核心思想

定义一个二维数组：

```
dp[i][j] = 以 A[i-1] 结尾 且 以 B[j-1] 结尾 的最长公共子串长度
```

**为什么要"以...结尾"？** 因为子串要求连续，如果我们知道"以某两个字符结尾能匹配多长"，就可以借助**前一个字符的匹配结果**往后递推，而不用每次都从头比较。这是 DP 解决"连续"类问题的经典套路。

### 状态转移方程

想象你在同时逐个字符地比较两个字符串：

- **如果当前两个字符相等**（`A[i-1] == B[j-1]`）：
  说明可以把"前一步已经匹配上的长度"接着延长 1 位，即：

  ```
  dp[i][j] = dp[i-1][j-1] + 1
  ```

- **如果当前两个字符不相等**：
  说明连续匹配到这里就断了，重新计数：
  ```
  dp[i][j] = 0
  ```
  （这里跟"最长公共子序列"不一样，子序列不相等时是取 `max(dp[i-1][j], dp[i][j-1])`，但子串要求连续，一旦断了就必须清零重新开始，这是两者最大的区别）

### 举个例子直观感受一下

比如 A = "abcde"，B = "abfde"：

|     | ""  | a   | b   | f   | d   | e   |
| --- | --- | --- | --- | --- | --- | --- |
| ""  | 0   | 0   | 0   | 0   | 0   | 0   |
| a   | 0   | 1   | 0   | 0   | 0   | 0   |
| b   | 0   | 0   | 2   | 0   | 0   | 0   |
| c   | 0   | 0   | 0   | 0   | 0   | 0   |
| d   | 0   | 0   | 0   | 0   | 1   | 0   |
| e   | 0   | 0   | 0   | 0   | 0   | 2   |

- 走到 A="ab" 和 B="ab"时，因为 b==b 且前面 a==a，所以 dp=2（"ab"是公共子串）
- 走到 A="abc" 和 B="abf" 时，c ≠ f，直接清零
- 走到 A="abcd" 和 B="abfd" 时，d==d，但**前一步 dp[i-1][j-1]（对应c和f）已经是0**，所以只能重新算 dp=1
- 走到最后 e==e，往前一步 d==d 是 1，所以 dp = 1+1 = 2（"de"）

**整个过程中出现过的最大值就是答案**，这里是 2（"ab" 或 "de"，长度都是2）。

这里 dp 是一个 (len(A)+1) × (len(B)+1) 的二维数组，多开一行一列是为了方便处理"空字符串"这种边界情况（第0行、第0列全部初始化为0，表示和空串比较肯定没有公共子串）。

### Go 代码（二维数组版本，完整可运行）

```Go
package main

import "fmt"

// LongestCommonSubstring2D 使用二维 DP 数组，返回字符串 a 和 b 的最长公共子串。
// 时间复杂度 O(m*n)，空间复杂度 O(m*n)。
func LongestCommonSubstring2D(a, b string) string {
	// 边界情况：任一字符串为空，直接返回空串
	if len(a) == 0 || len(b) == 0 {
		return ""
	}

	ra, rb := []rune(a), []rune(b) // 用 rune 避免多字节字符（如中文）被截断
	m, n := len(ra), len(rb)

	// dp[i][j] 表示：以 ra[i-1] 结尾、以 rb[j-1] 结尾的最长公共子串长度
	// 多开一行一列（第0行、第0列），代表和空字符串比较，值全部是 0
	dp := make([][]int, m+1)
	for i := range dp {
		dp[i] = make([]int, n+1)
	}

	maxLen := 0    // 记录目前为止的最长长度
	endIndexA := 0 // 记录最长公共子串在 a 中的结束位置，方便最后截取结果

	for i := 1; i <= m; i++ {
		for j := 1; j <= n; j++ {
			if ra[i-1] == rb[j-1] {
				dp[i][j] = dp[i-1][j-1] + 1
				if dp[i][j] > maxLen {
					maxLen = dp[i][j]
					endIndexA = i
				}
			} else {
				dp[i][j] = 0
			}
		}
	}

	if maxLen == 0 {
		return ""
	}
	return string(ra[endIndexA-maxLen : endIndexA])
}

func main() {
	tests := []struct {
		a, b string
	}{
		{"abcde", "abfde"},
		{"abcdxyz", "xyzabcd"},
		{"", "abc"},
		{"abc", "abc"},
		{"abc", "def"},
	}

	for _, t := range tests {
		result := LongestCommonSubstring2D(t.a, t.b)
		fmt.Printf("a=%q, b=%q => 最长公共子串=%q (长度=%d)\n",
			t.a, t.b, result, len([]rune(result)))
	}
}
```

手动过一遍，对照代码看

还是用 A="abcde"，B="abfde"，完整的二维表长这样（行是 A，列是 B）：

    ""	a	b	f	d	e

"" 0 0 0 0 0 0
a 0 1 0 0 0 0
b 0 0 2 0 0 0
c 0 0 0 0 0 0
d 0 0 0 0 1 0
e 0 0 0 0 0 2

对照代码的双层循环，i 是行（对应 A 的字符），j 是列（对应 B 的字符）：

i=1 (a), j=1 (a)：ra[0]='a', rb[0]='a'，相等 → dp[1][1] = dp[0][0] + 1 = 0+1 = 1，此时 maxLen=1，endIndexA=1
i=2 (b), j=2 (b)：ra[1]='b', rb[1]='b'，相等 → dp[2][2] = dp[1][1] + 1 = 1+1 = 2，此时 maxLen=2，endIndexA=2
i=3 (c), j=3 (f)：不相等 → dp[3][3] = 0
……继续往下走，直到
i=5 (e), j=5 (e)：相等 → dp[5][5] = dp[4][4] + 1。而 dp[4][4] 对应的是 d 和 d（i=4, j=4），也相等，dp[4][4] = dp[3][3] + 1 = 0+1 = 1。所以 dp[5][5] = 1+1 = 2

最终 maxLen=2，第一次达到2的位置是 endIndexA=2（对应"ab"），所以结果是 ra[2-2:2] = ra[0:2] = "ab"。

这个版本和一维版本的关系

你会发现，这个二维版本里，每次算 dp[i][j] 时用到的 dp[i-1][j-1]，其实就是"上一行、左边挪一格"的那个值——一维滚动数组要解决的问题，就是怎么在只有一行空间的情况下，还能拿到这个"上一行"的值。

建议你先把这个二维版本自己跑一遍、跟着表格手动填一遍，等你能徒手画出这张表、并且清楚每个格子是怎么算出来的，再回头看一维滚动版本，你会发现那个 prev/temp 的技巧其实就是在模拟"如果我只有一行内存，怎么才能记住马上要被覆盖掉的旧值"，到时候理解起来会容易很多。

### 空间优化（面试加分点）

你会发现 `dp[i][j]` 只依赖**上一行**的数据（`dp[i-1][j-1]`），所以完全没必要开一个二维数组，**用一维数组滚动**即可，把空间复杂度从 O(m×n) 降到 O(n)。

**唯一要注意的坑**：因为一维数组是"复用"的，当你更新 `dp[j]` 时，你需要的是"上一轮"的 `dp[j-1]`（也就是左上角的值），但这个位置可能已经被这一轮更新覆盖了，所以要用一个临时变量提前存一下"左上角的值"。这是这道题从二维压缩到一维时最容易犯错的地方。

## 四、Go 代码实现

```go
package main

import "fmt"

// LongestCommonSubstring 返回字符串 a 和 b 的最长公共子串。
// 时间复杂度 O(m*n)，空间复杂度 O(min(m,n))。
func LongestCommonSubstring(a, b string) string {
	// 边界情况：任一字符串为空，直接返回空串
	if len(a) == 0 || len(b) == 0 {
		return ""
	}

	// 让 b 始终是较短的字符串，压缩空间时用较小的那个维度
	if len(a) < len(b) {
		a, b = b, a
	}

	ra, rb := []rune(a), []rune(b) // 用 rune 而不是 byte，避免中文等多字节字符被截断

	n := len(rb)
	dp := make([]int, n+1) // dp[j] 表示：以 a 当前遍历到的字符、以 rb[j-1] 结尾的最长公共子串长度

	maxLen := 0    // 记录目前为止的最长长度
	endIndexB := 0 // 记录最长公共子串在 b 中的结束位置（用于最后截取结果）

	for i := 1; i <= len(ra); i++ {
		prev := 0 // 保存左上角 dp[i-1][j-1] 的值，滚动数组的关键变量
		for j := 1; j <= n; j++ {
			temp := dp[j] // 先把当前 dp[j]（也就是下一轮的"左上角"）存起来
			if ra[i-1] == rb[j-1] {
				dp[j] = prev + 1
				if dp[j] > maxLen {
					maxLen = dp[j]
					endIndexB = j // 记录结束位置，方便还原子串
				}
			} else {
				dp[j] = 0
			}
			prev = temp // 更新 prev，供下一次循环（j+1）使用
		}
	}

	if maxLen == 0 {
		return ""
	}
	return string(rb[endIndexB-maxLen : endIndexB])
}

func main() {
	tests := []struct {
		a, b string
	}{
		{"abcde", "abfde"},
		{"abcdxyz", "xyzabcd"},
		{"", "abc"},
		{"abc", "abc"},
		{"abc", "def"},
		{"中华人民共和国", "中华共和国"},
	}

	for _, t := range tests {
		result := LongestCommonSubstring(t.a, t.b)
		fmt.Printf("a=%q, b=%q => 最长公共子串=%q (长度=%d)\n",
			t.a, t.b, result, len([]rune(result)))
	}
}
```

## 五、代码里几个"规范性"细节，面试时可以主动讲出来加分

1. **用 `[]rune` 而不是直接按 `byte` 遍历**：如果字符串里有中文等多字节字符，按 byte 处理会把一个汉字拆散，导致结果错误。这是很多人容易忽略的边界问题。
2. **边界处理**：任一输入为空串，直接返回空，不要让程序 panic 或死循环。
3. **让较短的字符串作为内层数组**：不影响正确性，但能进一步节省内存（尤其两个字符串长度差很大时）。
4. **变量命名语义清晰**：`maxLen`、`endIndexB`、`prev` 这种命名，别人一看就懂在干嘛，不用注释也能读懂大概逻辑。
5. **函数只做一件事**：`LongestCommonSubstring` 只负责计算，`main` 里单独写测试用例，职责分离，方便单测。

## 六、复杂度总结（面试一定会问）

| 方案                        | 时间复杂度      | 空间复杂度      |
| --------------------------- | --------------- | --------------- |
| 暴力解法                    | O(m·n·min(m,n)) | O(1)            |
| 二维 DP                     | O(m·n)          | O(m·n)          |
| **一维滚动 DP（本文实现）** | **O(m·n)**      | **O(min(m,n))** |

如果面试官继续追问"能不能更快"，可以提一句：**后缀数组 / 后缀自动机（Suffix Automaton）**能把时间复杂度做到 O(m+n)，但实现复杂度高很多，工程上一般 DP 已经够用，除非是超大规模字符串匹配场景才会用到后缀自动机这类更高阶的数据结构。这句话点一下就好，不需要展开讲，除非面试官真的深挖。
